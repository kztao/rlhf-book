# 训练概述

在本章中，我们对 RLHF 训练进行粗略概述，具体细节将在本书后面展开。
RLHF 虽然优化的是一个简单的损失函数，但涉及按顺序训练多个不同的 AI 模型，然后在复杂的在线优化中将它们链接在一起。

在这里，我们介绍 RLHF 的核心目标：使用基于距离的正则化项来优化人类偏好的代理奖励（并展示它如何与经典 RL 问题相关联）。
然后，我们展示使用 RLHF 创建领先模型的标准方案，以说明 RLHF 如何与其他后训练方法配合。
这些示例方案将在本书后面作为参考，当我们描述进行 RLHF 时的不同优化选择时，我们将回顾不同关键模型在训练中如何使用不同的步骤。

## 问题表述

基于人类反馈的强化学习（RLHF）的优化建立在标准 RL 设置之上。
在 RL 中，智能体从策略 $\pi(a_t\mid s_t)$ 中采样动作 $a_t$，给定环境状态 $s_t$，以最大化奖励 $r(s_t,a_t)$ [@sutton2018reinforcement]。
策略是将每个状态映射到动作上概率分布的函数。
早期演化为现代 RLHF 文献的策略属于所谓的深度强化学习——即使用神经网络来学习上述函数。
传统上，环境根据转移（动力学）$p(s_{t+1}\mid s_t, a_t)$ 以及初始状态分布 $\rho_0(s_0)$ 演化。
策略和动力学共同决定了一个轨迹分布。
轨迹的总体概率是初始状态概率、策略所做的每个动作选择以及环境产生的每个状态转移的乘积：

$$p_{\pi}(\tau)=\rho_0(s_0)\prod_{t=0}^{T-1}\pi(a_t\mid s_t)\,p(s_{t+1}\mid s_t,a_t).$$ {#eq:rl_dynam}

在具有时间范围 $T$ 的有限回合中，RL 智能体的目标是解决以下优化问题，其中 $\gamma$ 是一个从 0 到 1 的折扣因子，用于平衡短期奖励与未来奖励的可取性：

$$\max_\pi \; \mathbb{E}_{\tau \sim p_{\pi}} \left[ \sum_{t=0}^{T-1} \gamma^t r(s_t, a_t) \right].$$ {#eq:rl_opt}

给定策略的期望回报通常记为 $J(\pi)$，最优值记为 $J^* = \max_\pi J(\pi)$。

对于持续性任务，通常取 $T\to\infty$ 并依赖折扣（$\gamma<1$）来保持目标的良好定义。
优化此表达式的多种方法在第 6 章中讨论。

### 一个简单示例：恒温器 {#example-rl-thermostat}

为了建立对 RL 做什么的基本直觉，考虑一个试图将房间保持在 70$^\circ$F 目标温度的恒温器。
在 RL 中，智能体开始时对任务一无所知，必须通过试错发现一个好的策略。
恒温器示例有以下组成部分（每个部分如何映射到 @eq:rl_dynam 中的轨迹分布见 @fig:thermostat-equation）：

- **状态（$s_t$）**：当前房间温度，例如 65$^\circ$F。
- **动作（$a_t$）**：打开或关闭加热器。
- **奖励（$r$）**：温度在目标温度 2$^\circ$ 以内时 +1，否则为 0。
- **策略（$\pi$）**：决定根据当前温度打开或关闭加热器的规则。以下是恒温器可能学到的一个策略，根据环境的具体转移动力学，该策略可能不是最优的：

$$\pi(a_t = \text{on} \mid s_t) = \begin{cases} 1 & \text{若 } s_t < 70^{\circ}\text{F} \\ 0 & \text{其他} \end{cases}$$ {#eq:thermostat_policy}

- **转移**：当加热器打开时房间变暖，关闭时变凉。智能体通过其动作影响这些动力学，但底层物理——房间加热或冷却的速度——不在其控制范围内。

![轨迹分布（@eq:rl_dynam）中的每一项映射到恒温器 RL 示例。](images/thermostat_equation.png){#fig:thermostat-equation .center}

最初，恒温器的策略基本上是随机的——它不在意当前温度地开关加热器，房间的温度剧烈波动。
经过多个回合的试错，智能体发现当房间冷时打开加热器、当它热时关闭可以获得更多奖励，并逐渐收敛到一个合理的策略。
这就是核心的 RL 循环：观察状态，选择动作，接收奖励，并更新策略以随着时间获得更多奖励。

### 经典 RL 示例：CartPole

对于一个更丰富的具有连续动力学的示例，考虑经典的 *CartPole*（倒立摆）控制任务，它出现在许多 RL 教科书、课程甚至研究论文中。
恒温器只有一个状态变量和一个二元动作，而 CartPole 涉及四个连续状态变量和基于物理的转移——使其成为 RL 算法的标准基准。

![CartPole 环境，展示状态变量（$x$、$\dot{x}$、$\theta$、$\dot{\theta}$）和动作（$\pm F$）。](images/cartpole.png){#fig:cartpole width=400px .center}

- **状态（$s_t$）**：小车位置/速度和摆杆角度/角速度：

  $$s_t = (x_t,\,\dot{x}_t,\,\theta_t,\,\dot{\theta}_t).$$ {#eq:cartpole_state}

- **动作（$a_t$）**：对小车施加左/右水平力，例如 $a_t \in \{-F, +F\}$。

- **奖励（$r$）**：一个简单的奖励是，当摆杆保持平衡且小车保持在轨道上时（例如 $|x_t| \le 2.4$ 且 $|\theta_t| \le 12^\circ$），每一步 $r_t = 1$，当任一界限被违反时回合终止。

- **动力学 / 转移（$p(s_{t+1}\mid s_t,a_t)$）**：在许多环境中，动力学是确定性的（因此 $p$ 是一个点质量），可以通过欧拉积分以步长 $\Delta t$ 写为 $s_{t+1} = f(s_t,a_t)$。标准简化的 CartPole 更新使用常量小车质量 $m_c$、摆杆质量 $m_p$、摆杆半长度 $l$ 和重力 $g$（$\alpha$ 是一个带加速度单位的质量归一化中间量）：

  $$\alpha = \frac{a_t + m_p l\,\dot{\theta}_t^2\sin\theta_t}{m_c + m_p}$$ {#eq:cartpole_temp}

  $$\ddot{\theta}_t = \frac{g\sin\theta_t - \cos\theta_t\,\alpha}{l\left(\tfrac{4}{3} - \frac{m_p\cos^2\theta_t}{m_c + m_p}\right)}$$ {#eq:cartpole_angular_accel}

  $$\ddot{x}_t = \alpha - \frac{m_p l\,\ddot{\theta}_t\cos\theta_t}{m_c + m_p}$$ {#eq:cartpole_linear_accel}

  $$x_{t+1}=x_t+\Delta t\,\dot{x}_t,\quad \dot{x}_{t+1}=\dot{x}_t+\Delta t\,\ddot{x}_t,$$ {#eq:cartpole_pos_update}
  $$\theta_{t+1}=\theta_t+\Delta t\,\dot{\theta}_t,\quad \dot{\theta}_{t+1}=\dot{\theta}_t+\Delta t\,\ddot{\theta}_t.$$ {#eq:cartpole_angle_update}

这是上述通用设置的具象实例：策略选择 $a_t$，转移函数推进状态，奖励在回合中累积。

### 调整标准 RL 设置

RLHF 的 RL 表述被看作是一个不那么开放式的问题，其中 RL 的几个关键部分被设定为特定定义以适应语言模型。
从标准 RL 设置到 RLHF 有多个核心变化：
表 @tbl:rl-vs-rlhf 总结了标准 RL 与用于语言模型的 RLHF 设置之间的这些差异。

1. **从奖励函数切换到奖励模型。** 在 RLHF 中，使用学习的人类偏好模型 $r_\theta(s_t, a_t)$（或任何其他分类模型）而不是环境奖励函数。这使设计者在方法的灵活性和对最终结果的控制上获得了显著提升，但代价是实现复杂性。在标准 RL 中，奖励被视为环境中无法由设计学习智能体的人改变或操纵的静态部分。
2. **不存在状态转移。** 在 RLHF 中，领域的初始状态是从训练数据集中采样的提示，而"动作"是对该提示的补全（在标准 RLHF 设置中，提示是固定的，模型的补全不定义下一个提示）。一个提示和一个补全的组合构成一个完整的回合或 rollout，这在经典 RL 问题中将是许多重复的状态-动作、状态-动作链。
3. **回答级奖励且无折扣。** RLHF 中奖励的归属是针对由多个生成的 token 组成的整个动作序列，而不是以细粒度的方式进行（这种单步结构在 RL 文献中有时被称为赌博机问题）。为了帮助 RLHF 的 RL 算法将每个 token 视为同一动作的一部分，实现通常使用 $\gamma = 1$（无折扣）的折扣因子，这与标准 RL 不同，标准 RL 中 $\gamma < 1$ 用于在许多顺序决策中平衡短期和长期奖励。

::: {.table-wrap}
| 方面 | 标准 RL | RLHF（语言模型） |
|---|---|---|
| 策略 | 从零开始学习（随机初始化） | 从预训练语言模型微调 |
| 奖励信号 | 环境奖励函数 $r(s_t,a_t)$ | 学习的奖励 / 偏好模型 $r_\theta(x,y)$（提示 $x$，补全 $y$） |
| 状态转移 | 有：动力学 $p(s_{t+1}\mid s_t,a_t)$ | 通常没有：提示 $x$ 从数据集采样；补全不定义下一个提示 |
| 动作 | 单个环境动作 $a_t$ | 从 $\pi_\theta(\cdot\mid x)$ 采样的一个补全 $y$（一个 token 序列） |
| 奖励粒度 | 通常是每步 / 细粒度 | 通常是回答级（赌博机风格），覆盖整个补全，通常无折扣（$\gamma = 1$） |
| 时间范围 | 多步回合（$T>1$） | 通常是单步（$T=1$），尽管多轮可以建模为更长的时间范围 |
表：标准 RL 与用于语言模型的 RLHF 之间的关键差异。 {#tbl:rl-vs-rlhf}
:::

鉴于问题的单轮性质，优化可以重新写为不包含时间范围和折扣因子（并使用显式奖励模型）：
$$\max_\pi \; \mathbb{E}_{\tau \sim \pi} \left[r_\theta(s_t, a_t) \right].$$ {#eq:rl_opt_int}

在许多方面，结果是，虽然 RLHF 很大程度上受 RL 优化器和问题表述的启发，但实际实现与传统 RL 非常不同。

### 微调与正则化

在传统 RL 问题中，智能体必须从随机初始化的策略学习，但使用 RLHF 时，我们从一个具有许多初始能力的强大预训练基础模型开始。
RLHF 的这个强先验引发了一个需求：防止优化从初始策略漂移太远。
为了在微调机制中成功，RLHF 技术采用多种类型的正则化来控制优化。
目标是允许奖励最大化仍然发生，而不让模型屈服于过度优化，如第 14 章所讨论的。
优化函数最常见的改变是添加一个 KL 散度惩罚项，衡量当前 RLHF 策略与优化起点之间的距离。训练模型时设置的 $\beta$ 超参数控制此约束的强度——较大的 $\beta$ 使模型更接近其起点，而较小的 $\beta$ 使优化器有更多自由去追逐奖励：

$$\max_\pi \; \mathbb{E}_{\tau \sim \pi} \left[r_\theta(s_t, a_t)\right] - \beta  \mathcal{D}_{\text{KL}}(\pi(\cdot|s_t) \| \pi_{\text{ref}}(\cdot|s_t)).$$ {#eq:rlhf_opt_eq}

在这个表述框架内，大量关于 RLHF 训练的研究都致力于理解如何花费一定的"KL 预算"，该预算通过距离初始模型的距离来衡量。
更多细节见第 15 章正则化。

### 优化工具

在本书中，我们详细介绍了许多解决此优化问题的流行技术。
流行的后训练工具包括：

- **奖励建模**（第 5 章）：训练一个模型来捕获收集到的偏好数据中的信号，然后能够输出表示未来文本质量的标量奖励。
- **指令微调**（第 6 章）：RLHF 的先决条件，通过模仿预选的示例，教导模型在当今大多数语言建模交互中使用的问答格式。
- **拒绝采样**（第 9 章）：最基本的 RLHF 技术，通过模仿人类偏好的奖励模型过滤指令微调的候选补全。
- **策略梯度**（第 6 章）：在 RLHF 的开创性示例中使用的强化学习算法，根据奖励模型的信号更新语言模型的参数。
- **直接对齐算法**（第 8 章）：直接从成对偏好数据优化策略的算法，而不是学习中间奖励模型然后再优化。

现代 RLHF 训练的模型总是使用指令微调，然后混合使用其他优化选项。

### RL 在后训练语言模型中的微妙优势

在接下来的章节中，我们涵盖了许多后训练的优化工具。
其中很多——如拒绝采样（第 9 章）和直接对齐算法如 DPO（第 8 章）——比让 RL 工作起来简单得多。
然而，尽管替代方案更简单，基于 RL 的方法仍然胜出。
一些趋势，如可验证奖励的强化学习（RLVR）的推理时扩展是显而易见的，但 RL 已经证明是一种非常适合语言模型的优化工具。
实现 RL 需要比指令微调或类 DPO 算法更大得多的基础设施投资，但是，冒着过于口语化的风险，它提供的梯度更新"总体上对模型有很大帮助"。
这很难量化，但体现在几个反复出现的形式中：

- RL 阶段可以"修复"模型上的粗糙边缘，使模型更容易对话或更鲁棒（这可以通过训练使其在使用 vLLM 等推理工具时具有数值稳定性来实现）。其确切原因在文献中并不广为人知，但其真实性体现在今天 RL 日益增长的应用中。
- RL 可以外科手术式地进行——模型很好地学习提示分布在哪里，RL 倾向于不"挤压"模型的一般能力。一个很好的例子是 Tülu 3 仅对数学提示进行 RL 训练，同时保持在广泛任务套件上的能力 [@lambert2024t]。

总的来说，语言模型上的 RL 损失是鲁棒的、可扩展的、有效的和灵活的，这打开了全新的实验领域。
引领我们走上这条道路的原始方法是 RLHF 工作。

## 经典的训练方案

随着时间的推移，各种模型已被确定为 RLHF 特定或后训练通用的经典方案。
这些方案反映了当时的数据实践和模型能力。
随着方案的过时，以相同特性训练模型变得更容易，所需的数据也更少。
后训练的一个普遍趋势是涉及更多的优化步骤、更多的训练算法、更多样化的训练数据集和评估。

### InstructGPT

大约在 ChatGPT 首次问世时，对语言模型进行后训练的广泛接受的（"经典的"）方法有三个主要步骤，其中 RLHF 是核心环节 [@lambert2022illustrating] [@ouyang2022training] [@bai2022training]。
在"基础"语言模型（在大规模网络文本上训练的下一个 token 预测模型）之上采取的三个步骤在下方 @fig:rlhf-basic-repeat 中总结：

1. **在约 1 万个示例上进行指令微调**：这教导模型遵循问答格式，并从主要由人类编写的数据中教授一些基本技能。
2. **在约 10 万对成对提示上训练奖励模型**（论文使用了 3.3 万个提示）：该模型从指令微调的检查点训练，捕获人们希望在最终训练中建模的多样化价值观。奖励模型是 RLHF 的优化目标。
3. **在另外约 10 万个提示上使用 RLHF 训练指令微调模型**（论文恰好使用了 3.1 万个，并且未记录提示是否从其他阶段重复使用）：模型根据奖励模型进行优化，使用可能独立的提示集，在收到评分之前生成回答。

一旦 RLHF 完成，模型就可以部署给用户了。该方案是现代 RLHF 的基础，但方案已经大幅演进，包含更多阶段和更多数据。

![早期三阶段 RLHF 流程的示意图：SFT、奖励模型，然后是优化。](images/rlhf-basic.png){#fig:rlhf-basic-repeat}

### Tülu 3

现代版本的后训练涉及更多的模型版本和训练阶段（即远远超过为 Llama 2 记录的 5 个 RLHF 步骤 [@touvron2023llama]）。
一个示例如下方 @fig:rlhf-complex 所示，模型在收敛之前经历了大量训练迭代。

![多轮现代后训练的示意图。](images/rlhf-complex.png){#fig:rlhf-complex}

这个时代及之后训练的最复杂模型尚未发布其训练过程的完整细节。
截至 2026 年，像 ChatGPT 或 Claude 这样的领先模型涉及许多轮迭代训练。
这甚至可能包括训练专门模型然后将权重合并在一起以获得能够执行许多子任务的最终模型 [@li2022branch]（例如 Cohere 的 Command A [@cohere2025command]）。

![Tülu 3 方案摘要，包含目标技能和多步骤训练方案。Lambert 等人 2024，许可证 CC-BY。](images/tulu3.png){#fig:tulu-3}

Tülu 3 是一个完全开源的多阶段后训练方法示例，其中 RLHF 发挥了重要作用。
Tülu 3 方案包括三个阶段：

1. **在约 100 万个示例上进行指令微调**：这个主要来自 GPT-4o 和 Llama 3.1 405B 等前沿模型混合的合成数据集，教导模型通用指令遵循，并作为数学和编程等能力的基础。
2. **约 100 万对偏好数据上的在线策略偏好数据**：此阶段显著提升模型的聊天性（例如 Arena，前身为 ChatBotArena，或 AlpacaEval 2），同时改善上述指令微调阶段提到的技能。
3. **在约 1 万个提示上进行可验证奖励的强化学习**：此阶段是小规模强化学习运行，以提升核心技能（如数学），同时保持总体性能（现在被视为现代推理模型如 DeepSeek R1 的先驱）。

该方案已成功应用于 Llama 3.1 [@lambert2024t]、OLMo 2 [@olmo20242] 和 SmolLM 模型 [@alrashed2024smoltulu]。

### DeepSeek R1

随着推理语言模型（如 OpenAI 的 o1）的兴起，后训练的最佳实践再次演进，重新排序并重新分配各训练阶段的计算资源。
推理模型后训练方案的最清晰文献是 DeepSeek R1 [@guo2025deepseek]，阿里巴巴更大的 Qwen 3 模型（即仅 32B 和 225B MoE 模型）[@yang2025qwen3] 或小米的 MiMo 7B [@xia2025mimo] 也反映了类似方案。
DeepSeek 方案如下：

1. **使用 10 万+ 在线策略推理样本进行"冷启动"**：该数据从早期 RL 检查点 R1-Zero 采样，并经过大量过滤以在 DeepSeek-V3-Base 上注入特定的推理过程。DeepSeek 使用术语"冷启动"来描述 RL 如何从很少的监督数据中学习。
2. **大规模强化学习训练**：此阶段反复用推理问题覆盖模型，在多种基准测试上运行 RLVR"直至收敛"。
3. **拒绝采样和 SFT**：接近收敛时，他们对 RL 检查点应用拒绝采样以构建约 80 万个样本的 SFT 数据集，然后在约 3/4 推理问题和 1/4 通用查询的过滤混合物上微调模型，以产生通用模型。
4. **混合强化学习训练**：在推理问题（可验证奖励）上使用通用偏好微调奖励模型来打磨模型。

如上所述，该方案存在演变，特别是在步骤 3 和 4 中，在将模型暴露给用户之前完成模型定稿。
许多模型从定制的指令数据集开始，其中包含从现有模型中大量过滤和打磨的思维链序列，提供一个快速的步骤，在进入 RL 之前仅通过 SFT 就能获得强大行为 [@seed2025seed]。
