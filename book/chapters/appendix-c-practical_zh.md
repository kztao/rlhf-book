# 实践问题

本附录涵盖了大规模运行后训练实验的实践考虑。
以一系列经验教训的形式呈现，而非连贯的叙事。

## 后训练的计算成本

有两种不同的方式来界定后训练运行的成本。
最大的成本是开发方案，这可能轻易达到最后几次训练运行计算的 10 倍到 100 倍。
次要成本，更容易衡量，是彻底应用方案的成本，这涉及多个种子、仔细评估、潜在的工程问题等。

对于第一个成本，要开发像 Tülu 3 [@lambert2024t] 这样的后训练方案，团队在拥有最终模型之前在 7B 规模上运行了数千次实验/评估。

对于最终运行，Olmo 3 报告详细说明了训练最终 32B Think 模型所涉及的内容 [@teamolmo2025olmo3]：

> 后训练遵循不同的操作模式，我们多次运行每个阶段，扫描学习率和其他超参数。用于后训练的理论，特别是 RL，发展得不那么完善，因此我们必须运行多个实验来识别给定基础模型的最优超参数。我们希望在未来工作中解决这个问题。
>
> 在后训练期间，检查点评估消耗了更大比例的计算资源，部分是由于推理模型在核心基准上的长生成。对于 SFT，我们扫描了四个候选学习率，每个使用 256 个 GPU，并行运行 36 小时。然后花费大约 12 小时进行评估、合并和检查点确认，总共大约两天。DPO 训练每次运行花费的时间更少（每个作业 64 个 GPU 的完整学习率扫描约 18 小时），但实际上由于集群不稳定而延长了数天。初始 Olmo 3 Think 32B 的最终 RL 运行跨越了大约 5 天，由于稳定性问题损失了至少一天的训练时间。在 Olmo 3 初始发布后，我们将最佳 RL 运行继续了另外 21 天在 224 个 GPU 上以生产 Olmo 3.1 Think 32B。

随着扩展强化学习成为更标准的实践，这将再次转变 [@khatri2025art]。

## 评估方差

后训练中一个未被充分认识的挑战是评估方差，特别是随着推理模型的兴起，需要使用温度高于 0 的采样来获得最佳评估分数。
不同基准具有截然不同的稳定性特征，由于提示难度的方差、评估集中的提示数量、被训练模型的脆弱性等。

在 Olmo 3 期间，团队跟踪了用于评估推理模型的不同评估的方差。

## 管理训练性能方差

在本书讨论的所有后训练方案和工具中，最终模型受到有意义的性能方差影响。
理解此方差的分布、其来源及其影响对于创建强模型至关重要。
训练最终模型的目标是通过改变训练参数和随机种子来采样许多点，以获得可能的最强模型。
注意，这是在模型*确实*更好和仅仅从评估噪声中重抽的收益之间的平衡。

在实践中，训练团队采取许多步骤来从他们的训练方案中捕获最大可能的价值：

1. 对每个最终模型运行扫描核心优化值，如学习率、批次大小等。
2. 在最佳设置上运行多个种子。随机种子可以对最终模型产生有意义的影响。
3. 模型合并被确立为用于创建强模型的关键工具。

## 识别糟糕的训练作业

在训练模型时建立一个重要的简单直觉是不同类型的模型问题。
你希望大部分时间花在当前数据、算法或方案不够好的问题上。
另一方面，有很多时候，在设置新方案时，某些方法就是坏的。

理解这一点的最佳方式是评估许多模型在基本静态的评估套件上。然后你会对哪些测试在后训练干预下难以改变产生直觉（通常是知识密集型评估如 MMLU）。
当后训练设置中出现某些非常、*非常*坏的事情时，这些基本稳定的评估通常会在一次训练作业中下降 10-20 分。
这是开发工具时最有用的信号之一！
